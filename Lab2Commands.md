# ЧАСТИНА 1. КОМАНДИ ТА ЇХ ПРАПОРЦІ

## 1.1. `dig` — головний інструмент діагностики

Загальний вигляд команди:

```bash
dig @СЕРВЕР ІМ'Я ТИП ПРАПОРЦІ
```

Розберемо на прикладі:

```bash
dig @192.168.106.10 red.color.edu A +short
```

| Частина | Що означає |
|---|---|
| `dig` | сама утиліта — "запитай DNS-сервер і покажи відповідь" |
| `@192.168.106.10` | **кому** відправити запит. Без `@адреса` dig піде на сервер із `/etc/resolv.conf` (тобто на той, що прописаний у системі за замовчуванням) |
| `red.color.edu` | **про що** питаємо — яке ім'я хочемо перетворити |
| `A` | **тип запису**, який нас цікавить (A = IPv4-адреса). Якщо не вказати тип — за замовчуванням буде `A` |
| `+short` | прапорець формату виводу |

### Прапорці dig (все, що з `+`)

| Прапорець | Що робить | Навіщо потрібен |
|---|---|---|
| `+short` | показати тільки саму відповідь (одна адреса чи ім'я), без службової інформації | швидко перевірити результат, зручно для скриптів |
| `+norecurse` (або `+noRD`) | сказати серверу: "не шукай сам, дай тільки те, що маєш" | перевірити, чи сервер **авторитетний** саме для цієї зони — якщо після цього прапорця відповідь все одно приходить, значить сервер справді відповідає авторитетно, а не бере з кешу |
| `+trace` | показати **весь ланцюжок** — від кореневого сервера до фінальної відповіді | наочно побачити, як працює ітеративний обхід ієрархії (корінь → .edu → color.edu) |
| `+noall +answer` | показати тільки секцію ANSWER, прибрати все інше | скоротити вивід, коли треба лише результат, але з TTL і типом запису |
| `+nostats` | прибрати статистику в кінці (час запиту, розмір повідомлення) | зробити вивід компактнішим |
| без прапорців | повний вивід: заголовок, прапорці (`flags:`), усі секції | базова, "розгорнута" перевірка — саме її варто робити на захисті |

### Типи запитів (те, що йде замість `A`)

| Тип | Що питаємо |
|---|---|
| `A` | IPv4-адресу за іменем |
| `AAAA` | IPv6-адресу за іменем |
| `NS` | хто є авторитетними серверами для цього домену |
| `SOA` | службові параметри зони (serial, refresh...) |
| `CNAME` | чи є в цього імені псевдонім і куди він веде |
| `PTR` | ім'я за адресою (працює разом з `-x`, дивись нижче) |
| `AXFR` | **повністю всю зону цілком** (це і є "передача зони") |
| `ANY` | усі типи записів одразу (у нових BIND часто обрізано з міркувань безпеки) |

### Особливі ключі dig (без `+`)

| Ключ | Що робить |
|---|---|
| `-x 192.168.22.10` | зворотний запит — "чиє це ім'я має ця адреса". dig сам перевертає адресу і дописує `in-addr.arpa`, тобі не треба робити це вручну |
| `-t AXFR` | те саме, що написати тип `AXFR` окремим словом |
| `-p 5353` | якщо DNS-сервер слухає нестандартний порт (у нас завжди 53, тому не знадобиться) |

### Як читати вивід dig (розбір "по буквах")

```
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 12345
;; flags: qr aa rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 2, ADDITIONAL: 3
```

* **status: NOERROR** — усе добре, помилки немає. Якщо імені не існує — буде `NXDOMAIN`. Якщо серверу заборонено відповідати — `REFUSED`. Якщо в конфізі помилка — `SERVFAIL`.
* **flags** — прапорці **відповіді** (буквено, кожна буква — окремий прапорець):
  * `qr` (query response) — це відповідь, а не запит
  * `aa` (**authoritative answer**) — **найважливіший прапорець для лабораторної**: означає, що відповів саме той сервер, що є "хазяїном" зони, а не хтось із кешу. Якщо `aa` немає — значить, відповідь узята звідкись-інде (з кешу рекурсивного резолвера)
  * `rd` (recursion desired) — клієнт **просив** сервер шукати самостійно
  * `ra` (recursion available) — сервер **вміє** так робити
* **QUERY: 1** — скільки було питань (завжди 1)
* **ANSWER: 1** — скільки записів у відповіді
* **AUTHORITY: 2** — скільки NS-записів (хто відповідає за зону)
* **ADDITIONAL: 3** — скільки "додаткових" записів (наприклад, A-адреси тих самих NS-серверів, щоб не робити ще один запит)

Секції у виводі:
* `;; ANSWER SECTION:` — сама відповідь
* `;; AUTHORITY SECTION:` — хто авторитетний
* `;; ADDITIONAL SECTION:` — супутня інформація

## 1.2. `host` — коротка версія dig

```bash
host red.color.edu 192.168.106.10
```

| Частина | Що означає |
|---|---|
| `red.color.edu` | ім'я, яке перевіряємо |
| `192.168.106.10` | сервер, якому направляємо запит (якщо не вказати — піде на системний DNS) |

Дає одразу коротку відповідь типу `red.color.edu has address 192.168.22.10` без прапорців і секцій — простіше читати, менше деталей для діагностики.

## 1.3. `nslookup` — інтерактивний режим

```
nslookup
> server 192.168.106.20
> set type=A
> white.color.edu
> exit
```

| Команда всередині nslookup | Що робить |
|---|---|
| `server 192.168.106.20` | перемкнути, якому серверу відправляти подальші запити (аналог `@адреса` в dig) |
| `set type=A` | вказати тип запису, який хочемо отримати (за замовчуванням `A`) |
| `set type=SOA` / `CNAME` / `PTR` / `NS` | те саме, тільки для інших типів |
| `white.color.edu` | саме ім'я, яке перевіряємо (просто вводимо його, без ключів) |
| `exit` | вийти з інтерактивного режиму |

## 1.4. Команди перевірки та керування BIND

### `named-checkconf`

```bash
named-checkconf
```

Перевіряє **синтаксис** усіх конфігураційних файлів (`named.conf`, `named.conf.options`, `named.conf.local`) — чи немає пропущеної крапки з комою, незакритих дужок тощо. Якщо все добре — команда **нічого не виводить** (мовчання = успіх). Якщо є помилка — покаже файл і номер рядка.

### `named-checkzone`

```bash
named-checkzone color.edu /etc/bind/zones/db.color.edu
```

| Частина | Що означає |
|---|---|
| `color.edu` | назва зони, яку перевіряємо (має **точно збігатися** з тим, що написано в `named.conf.local`) |
| `/etc/bind/zones/db.color.edu` | шлях до файлу з записами цієї зони |

Перевіряє синтаксис самого файлу зони (SOA один? Serial число? Немає дубльованих CNAME?). Успішний результат:

```
zone color.edu/IN: loaded serial 2026092001
OK
```

`loaded serial 2026092001` — підтверджує, який serial зараз прочитаний з файлу (корисно звірити, що ти дійсно зберіг файл після редагування).

### `rndc` (remote name daemon control) — керування сервером, що вже працює

| Команда | Що робить |
|---|---|
| `rndc reload` | перечитати **всі** зони без повної зупинки служби |
| `rndc reload color.edu` | перечитати **тільки одну** вказану зону (швидше й безпечніше, ніж усі) |
| `rndc retransfer color.edu` | (виконується на slave) — примусово, негайно перезабрати зону з master'а, не чекаючи Refresh/Notify |
| `rndc status` | показати загальний стан сервера: скільки зон, скільки запитів обслужено, чи включена рекурсія |
| `rndc flush` | очистити кеш рекурсивного резолвера (корисно, якщо перевіряєш зміни, а стара відповідь ще "застрягла" в кеші) |

### systemd-команди

| Команда | Що робить |
|---|---|
| `systemctl restart named` | повністю перезапустити службу DNS-сервера (перечитує геть усе, включно з опціями) |
| `systemctl enable named` | увімкнути автозапуск служби після перезавантаження машини |
| `systemctl status named` | показати, чи запущена служба, і останні рядки логу |
| `journalctl -u named -n 30 --no-pager` | показати останні 30 рядків логу саме цієї служби (`-n 30` — кількість рядків, `--no-pager` — вивести одразу в термінал, не відкриваючи постраничний перегляд) |
| `ss -lnptu \| grep :53` | перевірити, чи хтось слухає порт 53. `-l` = listening (лише ті, хто слухає), `-n` = показувати адреси числом, а не іменами, `-p` = показати назву процесу, `-t` = TCP, `-u` = UDP |

## 1.5. `tcpdump` для DNS (якщо треба показати трафік)

```bash
sudo tcpdump -i enp0s8 -n port 53
```

| Частина | Що означає |
|---|---|
| `-i enp0s8` | слухати саме цей мережний інтерфейс (той, що дивиться у VNet1) |
| `-n` | не перетворювати адреси в імена (щоб tcpdump сам не робив DNS-запити і не плутав картину) |
| `port 53` | фільтр — показувати тільки трафік DNS (і UDP, і TCP одразу, бо порт вказано без уточнення протоколу) |

У виводі звичайний запит буде позначено як `... UDP, length ...`, а передача зони (AXFR) — як частина TCP-сесії (буде видно `Flags [S]`, `[.]`, `[P.]` — це прапорці TCP-з'єднання: SYN, ACK, PUSH+ACK).

# ЧАСТИНА 2. РОЗБІР ФАЙЛІВ КОНФІГУРАЦІЇ

## 2.1. `named.conf.options`

```conf
acl "trusted" {
        127.0.0.1;
        192.168.106.0/24;
};
```

| Рядок | Що означає |
|---|---|
| `acl "trusted" { ... }` | створюємо **іменований список адрес** з назвою `trusted`, щоб не переписувати ці адреси кілька разів далі |
| `127.0.0.1;` | сама машина (localhost) |
| `192.168.106.0/24;` | уся наша лабораторна мережа |

```conf
options {
        directory "/var/cache/bind";
        recursion yes;
        allow-query { trusted; };
        allow-recursion { trusted; };
        forwarders { 8.8.8.8; 1.1.1.1; };
        dnssec-validation no;
        listen-on { 127.0.0.1; 192.168.106.10; };
        listen-on-v6 { none; };
};
```

| Директива | Що означає |
|---|---|
| `directory "/var/cache/bind";` | робоча папка сервера — сюди він пише тимчасові/отримані файли (важливо для slave!) |
| `recursion yes;` | дозволити серверу самому шукати відповіді для чужих доменів (тобто працювати ще й як звичайний резолвер) |
| `allow-query { trusted; };` | **хто взагалі має право** щось запитувати в цього сервера — тільки адреси зі списку `trusted` |
| `allow-recursion { trusted; };` | хто має право просити **рекурсивний** пошук (окрема настройка від простого allow-query, бо рекурсію зазвичай обмежують суворіше — щоб сервер не використовували для чужих атак) |
| `forwarders { 8.8.8.8; 1.1.1.1; };` | коли хтось питає про домен, що **не є нашою зоною** (наприклад google.com) — куди пересилати запит. Тут — публічні DNS Google та Cloudflare |
| `dnssec-validation no;` | вимкнути перевірку криптографічних підписів DNSSEC (наші зони не підписані, тому без цього будуть помилки `SERVFAIL`) |
| `listen-on { 127.0.0.1; 192.168.106.10; };` | на яких **своїх** адресах слухати вхідні запити |
| `listen-on-v6 { none; };` | не слухати IPv6 узагалі (у нас лабораторія тільки IPv4) |

## 2.2. `named.conf.local` — master (VM1)

```conf
zone "color.edu" {
        type master;
        file "/etc/bind/zones/db.color.edu";
        allow-transfer { 192.168.106.20; };
        also-notify { 192.168.106.20; };
        notify yes;
};
```

| Директива | Що означає |
|---|---|
| `zone "color.edu" { ... }` | опис однієї конкретної зони з іменем `color.edu` |
| `type master;` | ця машина — **джерело** даних, тут дозволено редагувати записи |
| `file "/etc/bind/zones/db.color.edu";` | де лежить файл із самими записами цієї зони |
| `allow-transfer { 192.168.106.20; };` | **кому дозволено скачати всю зону цілком** (AXFR) — тільки нашому slave. Без цього будь-хто міг би вивантажити всю структуру мережі |
| `also-notify { 192.168.106.20; };` | кому одразу повідомляти при зміні зони |
| `notify yes;` | увімкнути саму функцію оповіщення (NOTIFY) |

## 2.3. `named.conf.local` — slave (VM2)

```conf
zone "color.edu" {
        type slave;
        file "/var/cache/bind/db.color.edu";
        masters { 192.168.106.10; };
        allow-notify { 192.168.106.10; };
        allow-transfer { none; };
};
```

| Директива | Що означає |
|---|---|
| `type slave;` | ця машина **не редагує** зону сама, а отримує копію ззовні |
| `file "/var/cache/bind/db.color.edu";` | куди **зберегти отриману** копію (файл ще не існує — з'явиться сам після першої передачі) |
| `masters { 192.168.106.10; };` | **у кого** забирати дані — адреса первинного сервера |
| `allow-notify { 192.168.106.10; };` | від кого приймати сповіщення NOTIFY (щоб чужий сервер не міг обманом змусити нас "оновитись") |
| `allow-transfer { none; };` | заборонити **іншим** забирати зону вже з нашого (slave) сервера — не потрібно, щоб хтось третій тягнув копію з обох машин |

## 2.4. Файл прямої зони — розбір `db.color.edu` рядок за рядком

```dns
$TTL    3600
```
Значення TTL (у секундах) **за замовчуванням для всіх записів нижче**, якщо для конкретного запису TTL не вказано окремо. 3600 секунд = 1 година.

```dns
$ORIGIN color.edu.
```
"Суфікс за замовчуванням". Усі імена нижче, які написані **без крапки в кінці**, автоматично отримають дописане `.color.edu.` Тобто `red` перетвориться на `red.color.edu.`

```dns
@       IN      SOA     ns1.color.edu. admin.color.edu. (
                        2026092001      ; Serial
                        3600            ; Refresh
                        900             ; Retry
                        604800          ; Expire
                        86400 )         ; Negative Cache TTL
```

| Елемент | Що означає |
|---|---|
| `@` | скорочення "вершина поточної зони", тобто `color.edu.` (значення `$ORIGIN`) |
| `IN` | клас запису = Internet (завжди так, це історичний артефакт, інші класи практично не використовуються) |
| `SOA` | тип запису — "початок повноважень", обов'язковий один на зону, завжди перший запис |
| `ns1.color.edu.` | **MNAME** — ім'я первинного (master) сервера цієї зони |
| `admin.color.edu.` | **RNAME** — email адміністратора зони, де перша крапка замінює символ `@`. Тобто це `admin@color.edu` |
| `2026092001` | **Serial** — "номер версії" зони. Slave порівнює це число зі своєю копією: якщо на master'і число **більше** — забирає оновлення. Формат зазвичай ДАТА+номер за день |
| `3600` | **Refresh** — раз на скільки секунд slave сам перевіряє, чи не змінився serial на master'і |
| `900` | **Retry** — якщо master не відповів під час Refresh, через скільки секунд повторити спробу |
| `604800` | **Expire** — якщо master недоступний увесь цей час (тут: 7 днів), slave перестає вважати свою копію дійсною і припиняє відповідати на запити по цій зоні |
| `86400` | **Negative Cache TTL (Minimum)** — на скільки секунд кешувати **негативні** відповіді (коли когось не існує, NXDOMAIN) |

```dns
@       IN      NS      ns1.color.edu.
@       IN      NS      ns2.color.edu.
```
Два записи NS — кажуть усьому світу: "за зону `color.edu` відповідають сервери `ns1.color.edu` і `ns2.color.edu`". Саме через ці записи інші резолвери дізнаються, куди звертатись за цим доменом.

```dns
ns1     IN      A       192.168.106.10
ns2     IN      A       192.168.106.20
```
А ці записи кажуть, яка **IP-адреса** відповідає кожному з імен `ns1` і `ns2`. Це обов'язково — NS вказує лише на ім'я, а без A-запису це ім'я неможливо перетворити на адресу (був би "висячий" NS без адреси).

```dns
red     IN      A       192.168.22.10
green   IN      A       192.168.22.20
blue    IN      A       192.168.22.30
black   IN      A       192.168.22.40
white   IN      A       192.168.22.50
```
П'ять основних записів варіанту: кожне ім'я → своя IPv4-адреса. Це і є "ресурси зони" з таблиці завдання.

```dns
ws1     IN      CNAME   red
ws2     IN      CNAME   green
ws3     IN      CNAME   blue
ws4     IN      CNAME   black
ws5     IN      CNAME   white
```
Псевдоніми (aliases). `ws1` — це не окрема адреса, а просто "інше ім'я для того самого вузла `red`". Коли хтось запитує `ws1.color.edu`, сервер спочатку відповідає "це CNAME на `red.color.edu`", а потім одразу додає й адресу `red` (щоб клієнту не довелось питати вдруге).

## 2.5. Файл зворотної зони — розбір `db.192.168.22`

```dns
$ORIGIN 22.168.192.in-addr.arpa.
```
Тут суфікс інший — спеціальний домен `in-addr.arpa`, який використовується саме для зворотних (адреса→ім'я) запитів. `22.168.192` — це наша мережа `192.168.22.0/24`, записана **у зворотному порядку октетів**.

```dns
10      IN      PTR     red.color.edu.
```

| Елемент | Що означає |
|---|---|
| `10` | остання цифра адреси. Разом з `$ORIGIN` це розгортається в повне ім'я `10.22.168.192.in-addr.arpa.` — тобто "запис про адресу 192.168.22.10" |
| `PTR` | тип запису — "вказівник", зворотне перетворення: адреса → ім'я |
| `red.color.edu.` | **на що вказує** ця адреса. Обов'язково з крапкою в кінці (абсолютне ім'я) — інакше сюди сам допишеться `$ORIGIN` зворотної зони і вийде повна нісенітниця |

Решта рядків (20/green, 30/blue, 40/black, 50/white) — те саме для інших чотирьох адрес.

# ЧАСТИНА 3. ШПАРГАЛКА — "Я ЗАБУВ, ЩО РОБИТЬ ЦЯ КОМАНДА"

| Хочу зробити | Команда |
|---|---|
| Перевірити синтаксис усіх конфігів | `named-checkconf` |
| Перевірити синтаксис одного файлу зони | `named-checkzone ІМ'Я_ЗОНИ ШЛЯХ_ДО_ФАЙЛУ` |
| Застосувати зміни без перезапуску служби | `rndc reload` |
| Застосувати зміни лише в одній зоні | `rndc reload ІМ'Я_ЗОНИ` |
| Перезапустити службу повністю | `systemctl restart named` |
| Подивитись логи служби | `journalctl -u named -n 30 --no-pager` |
| Перевірити A-запис | `dig @СЕРВЕР ІМ'Я A` |
| Перевірити, хто NS зони | `dig @СЕРВЕР ЗОНА NS` |
| Перевірити параметри SOA | `dig @СЕРВЕР ЗОНА SOA` |

| Примусово оновити slave негайно | `rndc retransfer ЗОНА` (виконувати на slave) |
